# Generate self-contained skill references from canonical docs

Skill installers and Claude/Cowork uploads consume one skill directory at a time, so every shipped skill must retain local `references/` files. We author shared material only in root `AGENTS.md`, `CONTEXT.md`, and `docs/**`, declare each bundle in `skill-references.json`, record generated ownership and content digests in `skill-references.lock.json`, and generate checked-in skill-local copies through one materializer. Cleanup preflights every formerly generated path and removes content only when its digest still matches, so a conflict cannot produce partial deletion. Durable `skillTransitions` metadata carries ownership across renames and uses `null` for explicit retirement when removals and additions happen together. Packaging rejects every symlink in a skill tree so archives cannot dereference machine-local files. This preserves consumer locality while avoiding manual duplication; source symlinks and cross-skill dependencies were rejected because their behavior is not portable across hosted downloads, Windows checkouts, scanners, and selective installs.
