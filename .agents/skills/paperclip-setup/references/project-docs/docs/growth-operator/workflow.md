# Growth Operator Workflow

Growth Operator skills turn acquisition intent into a shared Paperclip-native strategy, then branch into inbound and outbound planning.

```text
intent -> growth-clarify -> growth-record-strategy -> inbound-plan-work / outbound-plan-work -> inbound-triage / outbound-triage -> execution
```

## 1. Intent

Intent is the operator's rough acquisition input, not a Paperclip entity by itself.

Examples:

- Build repeatable acquisition around construction operator walkthroughs.
- Align Ihor's LinkedIn inbound motion with outbound construction outreach.
- Create a Q3 growth strategy where inbound builds logistics expertise and outbound books operator walkthroughs.

## 2. Growth Clarify

Use `growth-clarify` when acquisition intent spans inbound and outbound, or when the operator needs a shared strategy before branch planning.

Resolve:

- acquisition outcome
- durable company goal and team goals
- durable channel or motion projects
- market, vertical, ICP, buyer, and persona
- wedge or painful workflow
- inbound role
- outbound role
- shared proof, source material, and artifact asks
- offer or CTA
- time horizon
- scope and non-goals
- success signals
- constraints, risks, approvals, validation, and stop conditions
- existing Paperclip goals, projects, parent issues, or campaign issues to connect to

## 3. Growth Record Strategy

Use `growth-record-strategy` after the operator approves a Growth Clarification Summary.

It materializes only the next missing Paperclip layer unless the operator approves a larger proposal.

Possible layers:

- durable acquisition company goal
- inbound or outbound team goal
- expertise, vertical, or motion team goal
- durable channel or motion project
- yearly strategy parent issue
- quarterly strategy parent issue
- monthly strategy parent issue
- inbound branch parent issue
- outbound branch parent issue
- campaign or experiment parent issue
- plan document on an existing parent issue

## 4. Branch Planning

Use branch-specific planning skills after the shared strategy exists.

Use `inbound-plan-work` for creator-led, content-led, channel-led, or trust-building work.

Use `outbound-plan-work` for lead sourcing, enrichment, personalization, sequencing, reply handling, and walkthrough booking work.

Planning creates `backlog`, unassigned structure. It must not assign agents, checkout work, move issues to `todo`, send messages, publish content, modify CRM records, or invoke heartbeats.

## 5. Triage And Execution

Use `inbound-triage` for inbound, creator-led, content-led, or channel-led work.

Use `outbound-triage` for lead sourcing, enrichment, personalization, sequencing, tool setup, reply handling, and walkthrough booking work.

Triage is recommendation-first. It may recommend status changes, blocker links, or comments, but it must ask for approval before mutating Paperclip.

## Deferred

The following are out of scope for v1:

- automatic email or LinkedIn sending
- CRM ownership
- deliverability infrastructure
- publishing or scheduling automation
- analytics dashboards
- full revenue attribution
- autonomous reply handling
- creating new execution agents
